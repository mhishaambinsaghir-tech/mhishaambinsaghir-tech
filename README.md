A modular, database-backed **CLI Hospital Management System** built completely from scratch using Python, SQLAlchemy ORM, and SQLite.

The application follows a layered architecture:

```text
Application Entry Point
        │
        ▼
Presentation / CLI Menus
        │
        ▼
Business Logic / Services
        │
        ▼
SQLAlchemy ORM Models
        │
        ▼
Database Infrastructure
        │
        ▼
SQLite
```

### Core Features

* Patient management
* Doctor management
* Department management
* Appointment scheduling
* Medical records
* Billing and payments
* Doctor availability management
* Appointment conflict detection
* Referential integrity validation
* Multi-field search
* CRUD operations
* Appointment status transitions
* Automatic bill calculation
* Payment state management

### Engineering Features

* Service-layer business logic

The project contains **six major domain models**:

`Patient` · `Doctor` · `Department` · `Appointment` · `MedicalRecord` · `Bill`

**Technologies:** Python · SQLAlchemy · SQLite · Pytest · OOP · Layered Architecture

# 🧠 How I Build

I believe in **understanding and owning the systems I build**, while also embracing modern AI-assisted development.

I don't view AI as a replacement for software engineering. I use it as a productivity multiplier.

My typical workflow looks like:

```text
Understand the Problem
        ↓
Research & Design
        ↓
Design the Core Architecture
        ↓
Implement Core Functionality
        ↓
Test & Validate
        ↓
Use AI to Accelerate Development
        ↓
Review & Understand the Generated Work
        ↓
Refactor & Integrate
        ↓
Test Again
        ↓
Document & Deploy
```

For projects where I'm learning a new concept or architecture, I prefer to **implement the core functionality myself first**.

This helps me understand:

* Why the architecture works
* How the individual components interact
* Where the difficult parts of the system are
* How data flows through the application
* How to debug the system independently
* How to extend the system later

Once the foundation is working, I use AI-assisted development tools to accelerate areas such as:

* Refactoring
* Debugging
* Test generation
* Documentation
* UI/UX iteration
* Exploring alternative implementations
* Researching unfamiliar technologies
* Prototyping
* Performance improvements
* Repetitive development tasks
* Feature expansion

I review and integrate AI-assisted output as part of the development process rather than treating generated code as something to blindly copy.

> **I build the foundation. AI helps me move faster.**

# 🧩 Engineering Principles

### Separation of Concerns

I prefer systems where presentation, business logic, data access, and infrastructure have clearly defined responsibilities.

### Build Before Abstracting

I prefer understanding the core problem and implementing a working foundation before introducing unnecessary abstraction.

### Validate Early

I try to validate assumptions through testing and actual execution rather than relying purely on theoretical design.

### Understand the Code

Whether code is written manually or developed with AI assistance, I believe the developer should understand the system they are responsible for.

### Practicality Over Complexity

A solution doesn't become better simply because it uses more technologies. I prefer choosing tools based on the actual problem.
